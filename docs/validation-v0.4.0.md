# 0.4.0 本机验证记录

状态：内部候选；桌面交互的最终验收尚未执行。没有发布 GitHub Release。0.3.0 已通过 PR #2 合并，本次继续使用同一虚拟机与数据。

## 功能与界面

- 主界面重组为七个工作区，保留独立安卓游戏窗口。普通应用/文件操作通过按钮和列表完成，JSON/Shell 集中在自动化页。
- GUI 与 CLI 使用共享服务。二进制 PNG 预览无需每帧写文件；状态与实例查询短缓存，写操作仍验证实例。界面日志限制为 1500 行/512 KiB，完成任务历史有界。
- 14 个离屏布局（七页、两种宽度）渲染成功，绑定错误为零。这不能代替真实鼠标、键盘、缩放和窗口验收。
- 实际管道传输的 960×540 预览成功解码；20 帧预览基准平均 119.77 ms、中位 86.84 ms、P95 313.04 ms，无逐帧文件。协调进程私有内存峰值增长约 11 MiB。
- 受控私有目录上传与目录导出已在当前 VM 实测，4096 字节自制数据往返 SHA-256 一致。没有导出账号数据库或皮肤私钥。另发现强停返回后 PID 可短暂残留，已增加进程退出确认。

## 显示与内存

固定 Emulator 37.1.11、Android 35 x86_64 镜像与现有 Root 不变。当前 GPU 实际为 NVIDIA RTX 4070 Laptop，使用 Host GPU；WHPX 可用。Malody 6.6.22 通过现有 ARM64 转译运行。

| 场景 | 配置 | 实际结果 |
|---|---|---|
| 安卓显示模式 | 1920×1080、请求 120 Hz | 实际 120.00001 Hz |
| Malody 菜单 | 4 GiB | 约 60.00 FPS；帧间隔 P95 26.40 ms |
| Malody 菜单 | 3 GiB | 约 59.80 FPS；P95 26.29 ms；单次最大 76.45 ms |
| In Falsus 六轨谱面早期采样 | 3 GiB、30 秒 | 约 107.86 FPS；P95 16.78 ms；最大 34.52 ms |
| 修正启动检查后再次加载皮肤 | 3 GiB | 有效覆盖 23.30 秒/30.20 秒采集；约 110.40 FPS，P95 12.29 ms，最大 317.92 ms |

帧数据来自 SurfaceFlinger 的 `actualPresentTime`，有限缓冲可能缺样；不是“稳定 120 FPS”，也不是完整输入延迟。实现依据是 AOSP 的 [FrameTracker](https://android.googlesource.com/platform/frameworks/native/+/master/services/surfaceflinger/FrameTracker.cpp)。菜单自身约 60 FPS。不同时间的主机负载会影响结果，不将这组样本当作严格性能优越性统计。

用户报告 4 GiB 测试把 Windows 内存推至 94%。已立即 sync 并停止该轮测试，没有重跑该配置。停止前 QEMU 驻留约 4.49 GiB、私有提交约 6.01 GiB；刚停止后宿主可用约 6.23 GiB。

改回 3 GiB 后，实际皮肤运行的两分钟采样有 56 个样本：QEMU 驻留最高 4075 MiB，私有提交最高 5830 MiB，宿主可用最低 1625 MiB，后来回升到约 3.1 GiB。容量仍受其他应用影响，不能宣称彻底消除高内存或证明不存在泄漏。未为凑齐 4 GiB 对照继续制造低内存负载。

## 内存保护的具体范围

默认安卓配额改为 3072 MiB。每次新启动检查：

- 可用物理内存至少为安卓配额 + 1536 MiB 预估额外驻留 + 系统余量。系统余量取总内存的 1/8，限制在 2048–4096 MiB。
- 可用提交空间至少为安卓配额 + 2560 MiB 预估额外提交 + 1024 MiB 余量。
- 这些是根据当前固定组件样本设置的准入估计，不是硬性内存上限。16 GiB 本机、3 GiB 配额时，物理余量门槛为 6656 MiB。
- 启动中每秒检查；协调进程运行时每两秒检查。物理可用低于总量 1/12（限制在 1024–2048 MiB）或提交余量低于 512 MiB，持续六秒后请求保存关机；物理低于 512 MiB 或提交低于 256 MiB 时不等待六秒。
- 只处理经过归属与运行会话验证的产品 VM。运行中的正常关机先取消调试、释放触点、执行 guest sync；保存失败会报错，不能声称已停机。不处理其他进程，不调整页面文件，不回收工作集制造假下降。
- 启动失败时，先尽力同步，再清理本次创建的模拟器进程树。协调进程被异常终止、系统已经无响应或来不及完成保存时，软件保护不能提供保证。

边界测试包括：物理/提交容量不足、缺少提交读数、短暂压力恢复、持续压力、严重压力立即触发、启动前拒绝且不执行客体写入。没有故意耗尽宿主内存来验证自动关机；实机测试验证了正常起停与受控负载，紧急分支证据来自自动化测试，不能混称为故障注入实测。

之后一次实际启动请求中，宿主可用仅 5411 MiB，低于本配置所需 6656 MiB。CLI 返回 `host_memory_low`，未创建模拟器进程；没有降低门槛来绕过这次拒绝。
