# 安卓调试工作台：日常操作

从原来的 **Rooted Android Game VM** 桌面快捷方式启动，即进入工作台。点击“启动安卓”，再打开安卓窗口。应用在模拟器原窗口里运行；工作台预览用于观察和定位操作。

左侧“应用管理”负责安装、打开和选择应用，“文件管理”负责双向传输，“诊断与记录”负责日志、录像和帧率采样。只有编写自动化时才需要进入“AI 与自动化”。底部“任务与结果”显示进度，可取消任务并打开本机记录。

## 安装和选择应用

1. 点击“打开安卓”。首次出现安卓 USB 调试授权提示时，在这个模拟器窗口允许本机连接。
2. 在“应用管理”选择 APK 并检查、安装。检查包名、版本和 ABI，保留已有数据，不降级。
3. 搜索应用名称或包名，从带真实名称和图标的列表选中目标，再打开、停止或进入“管理文件”。同名应用可通过包名区分，系统应用可切换显示。没有选中目标时，应用操作不可用，不自动选择列表第一项。
4. 应用专属内容由应用自身处理。核心不包含任何游戏的皮肤、谱面、登记或业务导入流程。

应用 APK 和用户数据不随产品分发。旧版专属任务与证据保留，不会自动续作；可扩展插件尚未交付。

## 看画面、点按和六指测试

- 先点“获取原始截图”。旁边显示原始尺寸、旋转、前台应用和实际截图后端。
- 在预览上单击、按住后松开或拖动。**松开鼠标后**，工作台才会发送这次手势。预检会增加开始操作前的等待，不能用它直接打音游。
- 时间要求较高的测试使用输入序列。在“AI 与自动化”页填入六指模板，根据截图调整坐标，再运行。
- 每个触点有独立的 `id`（0–9）。`pressure: 1` 表示按住，`pressure: 0` 表示松开。后续帧只列需要改变的触点；不列出的触点保持原状态。序列结束总会释放所属触点。
- 截图尺寸、旋转、运行会话或前台应用变化后，旧观察编号会被拒绝。请重新截图。输入坐标指向**保存的原始 PNG**；GUI 会处理预览缩放和旋转，CLI 会处理到原始触摸面板的转换。
- “取消当前任务”停止当前任务。“释放全部触点”先取消输入任务再释放。输入客户端超过 5 秒没有查询任务，协调进程也会取消它；`--wait` 会自动保持这个查询。

日志记录的是主机实际调用时间与计划时间的差值，不是安卓收到触摸、显示发光或播放声音的端到端延迟。Windows 调度、转译和渲染负载都会影响游戏表现。

## 文件上传和下载

在文件管理页选择安卓用户，按名称或包名搜索并选择应用。左侧列出该应用实际可用的私有、设备保护、外部、媒体和扩展目录；共享存储可以单独使用。未生成或未解锁的目录会说明原因。

- 双击文件夹、使用目录树、面包屑、后退和上一级导航。大目录通过“加载下一页”继续，不静默截断。支持 Ctrl/Shift 多选及 Enter 打开目录。
- “上传文件…”和“上传文件夹…”使用电脑选择器；也可把多个文件或文件夹拖到文件页。目标是当前安卓目录，顶层文件夹名称保留，无需输入包名或完整目标文件名。APK 在文件页也作为普通文件传输。
- “下载所选…”可同时下载文件和文件夹；“导出当前目录…”包含其嵌套内容和空目录。“导出应用数据…”先选数据根，再选电脑保存位置，各根独立分层。
- 冲突预览可选跳过、保留双方或备份后覆盖，目录合并保留目标额外内容。涉及私有一致性时显示需要停止的应用；名称或链接不能原样保存到 Windows 时，可改用 tar 归档。文件级导出不代表账号、系统密钥或跨设备可运行性已验证。
- 传输按块处理并检查 SHA-256。现有内容替换前保留 `.rgvm-backup-*`，逐项结果记载暂存、备份和完成状态。单计划最多100000项；具体空间不足或源/目标变化会拒绝执行。
- “取消当前传输”停止本次任务。“传输记录与恢复”提供结果、记录目录和明确续作入口；不会自动重放。取消时已提交的条目可能保留，需按账本核查；已失效计划应重新规划。

GUI 与 AI/CLI 使用同一套 `apps.list → files.roots/browse → files.transfer.plan/start/inspect` 接口。`files.transfer.list` 和 `session.summary` 提供恢复线索。旧版 `files.list/push/pull/export/diff/sync` 也接入共享根、计划和执行器，保留原字段；列表默认返回完整目录，可显式用 `pageSize/cursor` 分页，不再静默截取4096项。所有传输共用100000条目计划上限及8MiB分块，不再有旧512MiB单文件上限。

兼容请求仍使用 `package/scope/remote/local`，可另指定 `userId`（默认0）；`scope: shared` 的相对路径仍从该用户主存储的 **Download** 开始，不代表整个共享卷。`push` 的remote及 `pull` 的local是精确目标文件名；`sync/diff` 比较本地目录的内容，不额外嵌套本地顶层目录。sync保留目标多余文件，并传输空目录；diff只保存计划，不创建目标目录或复制内容。export保留 `directory/dataDirectory/includesPrivateData`，dataDirectory直接包含所选目录内容。

兼容写入返回 `planId/artifactDirectory/transfer`；取消或失败时，从进度的planId或错误所指账本查询 `files.transfer.inspect`，核查后明确 `files.transfer.resume`。不要重发旧写入命令来代替续作。私有数据默认 `stopped-app`；仍在运行时拒绝执行，可显式 `stopApplications: true` 停止该应用。读取可显式选择 `consistency: live`，结果不保证应用数据一致性；散列核验不表示App已经读入。

新计划可在source指定单个 `targetName` 改变目标名称。上传 `createParents: true` 配合 `destination.rootRef/relativePath` 会将缺失父目录按顺序写入计划和账本；规划阶段不创建它们，执行时仍验证目标变化与根边界。`contentsOnly: true` 用于目录内容传输，不能同时给该目录指定targetName。

计划的 `spaceChecks` 分卷列出预计增长、保留余量、实际可用容量和用途：目标数据、块暂存、归档缓存/最终归档、账本以及VM数据所在宿主卷。`paths` 最多展示12个样本，`totalPaths` 是该卷实际分配路径数。多个目标卷时，旧 `availableBytes` 不再用某一卷冒充全部容量；应读取各项spaceChecks。宿主保留既有512MiB磁盘余量，这不是单文件大小限制。规划按覆盖策略给出预览，执行会按实际冲突策略和已核验进度重算，skip/same不占复制空间。检查是当时的容量估算，不能预留或锁住其他程序可能使用的空间。

上传查询实际分配父目录所在文件系统，包含目录树中的嵌套挂载；同会话换卷会拒绝旧计划。归档缓存与最终文件可能在不同电脑磁盘，分别检查；同卷则按复制与归档阶段峰值合并。已有tar缓存不能抵扣最终归档所需空间。部分续作先核验实际暂存前缀，不直接采信旧offset。执行结果/执行头的 `spaceCheckPath` 指向带时间的本次容量依据，旧计划也会在执行时按新规则重验。

文件、应用目录元数据、日志/录屏/追踪及前台Shell请求会记录安卓端工具归属。`tools.list` 可在运行或停机时查看最近100条记录，`files.tools.list` 保留为兼容入口；错误中的 `guestCleanupPath`、传输结果中的 `guestToolToken/guestCleanupPath` 指向清理证据。`cleaned` 表示启动门已关闭且所属工具与登记诊断资源已核实清理；`pending` 不能当作已退出。恢复同一实例后可明确调用 `tools.cleanup`（参数token，兼容files.tools.cleanup），或由同计划 `files.transfer.resume` 先完成旧工具清理再续作。摘要提供对应恢复请求。其他实例拒绝处理；原VM会话结束不向新会话发送kill，仍需保存的诊断文件按记录核验处理。

`shell/root-shell` 是有界前台请求，分别保留shell UID与Root UID。普通子进程及同一登记进程组中清空环境变量的子进程都纳入清理；不能把这两个命令当作后台守护服务启动器。监督者身份无法核实时保持pending，不凭旧PID或进程名猜测kill。这不是恶意Root脚本的沙箱，不承诺约束主动脱离会话并抹去归属的程序，也不回滚脚本有意改变的文件或系统服务状态。

需要回退已完成的覆盖时，先从 `files.transfer.inspect` 的逐项账本核对实际backupPath。使用新引用读取该备份并校验，再以明确的新传输计划恢复原目标；恢复时同样备份当前版本。不要直接重放失败的旧写入。目录合并不是全批原子事务，回退范围应按已提交条目逐项确认；文件齐全也不代表应用内部数据库或跨设备还原已验证。

## 日志、录像和记录目录

“诊断与记录”页可以选择目标应用采集日志，跟随应用重启后的 PID。过滤框可搜索关键字，也可查看异常、崩溃和 ANR。日志丢失或达到上限会标记，不能将没有日志等同于没有问题。

日志到达请求时长正常完成；显式取消返回cancelled，logcat提前退出返回失败。过滤后的events.ndjson、受限原始stdout和stderr/退出记录一并保留。录屏取消后可用的部分文件也先校验并保存到本机，再删除guest副本；本机同名内容冲突或连接失败时保留guest原件并标pending，新的同类采集不会接管未恢复资源。文件SHA核验不等于播放器解码验证。追踪会核对内核tracing_on确已关闭；已有追踪运行时拒绝接管，不以进程退出代替内核状态。

内存、CPU 与可用的帧时序来自安卓诊断接口。Unity 的 SurfaceView 不一定提供 `gfxinfo` 帧数据，缺少时显示不可用。CPU 百分比可能累计多个核心，不能直接当作整台电脑的百分比。

“采样实际帧率”读取应用 SurfaceView 的呈现时间。报告可能缺样，会标明采样时间和有效覆盖；显示模式为 120 Hz 并不保证每一帧都达到 120 FPS。实时预览默认关闭，开启后最高约每秒四次，窗口失去焦点或最小化时暂停，避免额外占用。

## 内存偏高时怎么处理

“运行设置”建议从 **3072 MiB** 开始。这里分配的是安卓内存，模拟器本身、图形缓冲和 ARM64 转译还会占用 Windows 内存。本机试验中，3 GiB 安卓配置下模拟器驻留约 4 GiB，因此不能期待任务管理器只增加 3 GiB。

启动前会预留 Windows 余量；不足时明确说明所需和可用容量，保持安卓停止。运行期间持续严重低内存时，协调进程取消调试任务、释放触点，再执行保存和关机；失败会显示原因，不强杀其他程序。关闭工作台窗口后协调进程仍保留这项保护，只有安卓已停止时才能正常退出协调进程。

遇到拒绝启动，先关闭自己不需要的程序，再重试；也可降低安卓配额，但过低会让安卓内部应用更容易被系统回收。不要通过增大安卓内存来处理所有卡顿。无需修改 Windows 页面文件或安全设置。保护阈值与验证范围见性能记录，不能保证任意突发负载都不会耗尽整机内存。

录屏默认**无音频**，每次最多 180 秒。系统追踪按需采集。每次操作的目录位于当前资源根目录的 `debug-runs`，点击“打开记录目录”查看。日志、图像可能包含画面上显示的账号信息，分享前自行检查。

## 保存和恢复检查点

1. 点击“停机并建立检查点”。工具先让安卓 `sync`，确认产品模拟器完全退出，再复制磁盘。
2. 记下生成的检查点编号。检查点包含用户数据盘、加密密钥盘、配置、backing-file 关系及运行组件/系统镜像/Root ramdisk 指纹。
3. 需要恢复时，填入编号并点击“恢复此检查点”。工具先校验，再暂存和切换；当前磁盘另存为回退副本。恢复后冷启动并检查 ADB 和 Root。
4. 若进程或电脑在切换中断电，使用“恢复中断操作”，不要重新初始化 AVD。

检查点保存在资源根目录的 `checkpoints`。手动检查点不会自动删除，恢复留下的回退磁盘也需要你自行管理。保存或恢复都需要额外空间。资源迁移会带走检查点和记录，保留检查点内部原文件与散列；迁移后的恢复只调整暂存副本。

这是调试回滚功能，不是真机硬件密钥不可迁移的证明。旧检查点会恢复当时的应用与账号状态。

## 本机升级和公开发布的区别

`build/Build-LocalUpgrade.ps1` 生成明确标注 `UNSIGNED` 的本地候选，运行自动测试、独立安装/覆盖保留测试、PE 子系统检查和官方 SPDX 校验。测试安装使用单独的测试 AppId；正式安装仍使用原 AppId。

此流程不会执行 GitHub 发布。它也不替代 `Build-Release.ps1` 中原有的干净环境、签名、来源和公开发布门禁。具体哪些实机项目已完成、哪些仍待验证，见本次验收报告。
