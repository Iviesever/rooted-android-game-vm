# 给 AI 的本机调试流程

只使用安装目录的 `RootedAndroidGameVM.Cli.exe`。先执行 `help`、`schema`、`status`，不要扫描或接管 USB 手机，也不要启动第二个日常 AVD。

1. 检查状态与 `runtime.inspect`。若内存不足，停止启动尝试并说明容量；不能擅自结束用户其他程序。
2. `start --wait` 后确认 ADB、Root、前台与屏幕状态。读实际 PNG，再决定输入；黑屏或启动画面不代表应用已就绪。
3. 输入使用最新 `screen.id` 和原始 PNG 坐标。每个手指保留自己的 id；执行时使用 `--wait` 续期，结束、取消和断连都释放触点。记录的主机发送偏差不是端到端响应延迟。
4. 应用操作先检查版本与 ABI。通过 Malody 自身导入 `.msp` / `.mcz`；需要重载时用 `malody.reload`，并核对解包结果、画面和应用日志。由用户自己登录；设备绑定皮肤走原作者登记流程。
5. 只访问指定包名和目录。私有写入先停止应用，上传、下载、同步保留校验与备份。同步不删除额外文件；私有导出可能含秘密，默认只导出任务需要的小范围。
6. 长操作查看任务结果内层的 `ok`，不能把“已排队”当成成功。独立采集日志、截图与实际帧采样；不在性能测量同时编译软件。
7. 回滚前使用停机检查点，校验完整性并冷启动验证。检查点可能包含应用密钥，不能公开上传，也不能作为真机硬件绑定证明。

复杂请求写入 UTF-8 JSON 文件，再执行 `--request <文件> --wait`，避免 PowerShell 转义错误。执行前阅读 `schema` 返回的参数，不推测未支持的命令。

GUI 提供同一套流程。只有用户允许使用 computer-use 时才操作桌面界面；否则使用已授权的 CLI/ADB/gRPC 工作流。工作台有稳定的 AutomationId，例如 `Settings.Apply`、`Checkpoints.Table`；模拟器原窗口供高帧率游戏，工作台预览用于观察。
